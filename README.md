# Stage Manager Pro

Crea una web app mobile-first/PWA chiamata:

MALASTRANA

Eventi senza tempo

È un prototipo gestionale interno per Malastrana Eventi, società di eventi, spettacoli e produzioni immersive.

Usa come riferimento estetico le immagini allegate a questo prompt.

IMPORTANTE:

Le immagini sono riferimenti visivi per stile, palette, atmosfera, proporzioni, composizione e componenti.

NON copiare testi, nomi, date, informazioni o elementi imprecisi presenti nei mockup.

NON usare i nomi, le date o i dati delle immagini come dati reali.

==================================================

OBIETTIVO DELLA FASE

==================================================

Per ora voglio un prototipo UI/UX completo, navigabile e coerente, simile al prototipo precedente realizzato in Base44 ma più curato, ordinato e progettato per il futuro.

NON collegare ancora:

- Supabase;

- GitHub;

- database esterni;

- autenticazione reale;

- API;

- email;

- pagamenti;

- upload o storage reale;

- notifiche push;

- servizi esterni.

Usa solamente dati demo locali nel browser.

NON mostrare popup, richieste o messaggi per collegare Supabase o GitHub.

NON fingere che esistano sicurezza, login reale, ruoli protetti, database o backend.

Le logiche reali saranno costruite successivamente.

Il codice del prototipo deve comunque essere ordinato, modulare e facilmente collegabile in futuro a React/TypeScript, GitHub e Supabase.

==================================================

IDENTITÀ VISIVA

==================================================

L’app deve sembrare:

- proprietaria;

- elegante;

- editoriale;

- creativa;

- teatrale in modo misurato;

- fantasy/storica contemporanea;

- premium;

- chiara;

- professionale;

- flat;

- mobile-first.

L’app NON deve sembrare:

- una dashboard SaaS generica;

- un template Bootstrap;

- Notion;

- un’app viola/blu generata da AI;

- un clone Base44;

- una UI con card tutte uguali;

- un’interfaccia con gradienti casuali;

- un’interfaccia con ombre pesanti;

- un’app con angoli molto arrotondati ovunque;

- un prodotto cyberpunk o fantasy caricaturale.

Concept:

“LA REGIA DELL’INVISIBILE”

L’app deve evocare organizzazione, scena, produzione, avventura e cura dei dettagli, ma restare molto rapida e leggibile durante gli eventi.

==================================================

COMPATIBILITÀ ANDROID E iOS

==================================================

Questa app deve essere progettata come Progressive Web App mobile-first.

Deve funzionare correttamente su:

- Android tramite Chrome e installazione dalla schermata Home;

- iPhone/iOS tramite Safari e “Aggiungi a schermata Home”;

- tablet Android;

- iPad;

- desktop.

NON sviluppare due applicazioni separate.

Non usare interazioni che funzionano solo su Android o soltanto su iPhone.

Progetta l’interfaccia per touch screen, browser mobile e installazione PWA.

Verifica in particolare:

- safe area iPhone;

- area inferiore con home indicator;

- header non coperto da notch o Dynamic Island;

- bottom navigation che non finisca sotto la safe area;

- viewport stabile quando appare la tastiera;

- scroll naturale su Safari iOS e Chrome Android;

- nessuna interazione essenziale basata su hover;

- tap target grandi;

- layout utilizzabile con una mano;

- modali e bottom sheet compatibili con Safari iOS;

- form e tastiera mobile;

- selettori data e input usabili su Android/iOS;

- upload simulato compatibile concettualmente con fotocamera e galleria;

- nessun overflow orizzontale;

- nessun testo troncato;

- nessun contenuto coperto dalla bottom navigation.

Predisponi manifest PWA, icone placeholder e meta tag per una futura installazione.

NON implementare ora offline completo, push native o sincronizzazione offline.

NON dichiarare che l’app è già pubblicabile su App Store o Google Play.

La prima versione deve essere una PWA installabile.

REGOLE DEL PROTOTIPO

==================================================

- Usa solo stato locale/browser e dati demo.

- Non creare API esterne.

- Non simulare autorizzazioni reali.

- Non mostrare dati personali reali.

- Non dichiarare che login o ruoli siano sicuri.

- Non aggiungere servizi esterni.

- Non aggiungere pagamenti reali.

- Non aggiungere upload file reale.

- Non aggiungere notifiche push.

- Non creare componenti monolitici.

- Mantieni componenti modulari e riutilizzabili.

- Centralizza colori, font, spaziature, bordi e stati in design token.

- Prepara le strutture UI affinché possano essere collegate in futuro a Supabase senza rifare l’interfaccia.
